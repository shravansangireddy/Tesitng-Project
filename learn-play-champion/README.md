# Learn & Play Champion

A playful, responsive English and Math learning app for elementary learners, with adult-supported Pre-K exploration, a Grade 3–5 coding playground, and introductory AI discovery. Built with React, TypeScript, and Vite. Parents and teachers can sign in through Supabase to save private progress across devices. Guest play keeps progress only in this browser.

## Pre-K–Grade 5 practice library

Choose **Pre-K, Kindergarten, Grade 1, Grade 2, Grade 3, Grade 4, or Grade 5** using the grade selector on the dashboard or Adventures page. Each level includes **16 activities, 80 questions, one original story, and one original nonfiction text**: **560 questions, 112 level-specific activities, and 14 reading texts total**. English has seven activities per level; Math has nine. Titles, teaching tips, questions, and reading passages change with the selected level.

### Edit a grade pack

The seven files below are the source for the app's selected-level activities:

```text
src\content\grades\pre-k.txt
src\content\grades\kindergarten.txt
src\content\grades\grade-1.txt
src\content\grades\grade-2.txt
src\content\grades\grade-3.txt
src\content\grades\grade-4.txt
src\content\grades\grade-5.txt
```

Each UTF-8 file contains JSON with `grade` (`"prek"`, `"k"`, or `"1"`–`"5"`), `overview`, and `lessons`. Keep all sixteen IDs: `sight`, `vocabulary`, `spelling`, `reading`, `sentence`, `arithmetic`, `multiply`, `patterns`, `problems`, `geometry`, `informational`, `writing`, `place`, `fractions`, `measurement`, and `data`. Each lesson has a `title`, a `skill` description, and exactly five `questions`. Both `reading` and `informational` have a shared `passage` shown above their five questions.

Every question row has these **five positions, in this order**:

```text
["Question text", "Correct answer", ["Choice A", "Choice B", "Choice C"], "Hint", "Explanation"]
```

Spelling rows use `null` instead of a choices array because the answer is typed:

```json
["Type the word for a pet that barks.", "dog", null, "Say /d/ /o/ /g/.", "Dog is spelled d-o-g."]
```

Use 2–6 distinct choices for other activities, including the correct answer exactly. Multiple-choice grading is **case-sensitive** so capitalization exercises work; typed spelling ignores surrounding spaces and case. A `passage` can include `\n` for paragraphs. All prose is rendered as text, not HTML. Grade packs use explicit, reviewed Math questions rather than the old random templates. Review edited math for accuracy; validation cannot verify the meaning of arbitrary prose.

The six added lesson IDs also require a `guide`:

```json
{
  "standards": ["3.NBT.1"],
  "learn": "Explain the skill using an original worked example.",
  "together": "Describe a concrete adult-led activity and how to discuss the reasoning."
}
```

Use actual, verified codes for the file's grade. **Pre-K guides require `standards: []`; do not invent Pre-K CCSS codes or label Kindergarten codes as Pre-K alignment.** Validation checks code syntax, matching grade, uniqueness, and nonempty guidance, **not the existence of an arbitrary code or educational alignment**. Review changed references against official sources. Other lessons may optionally have a guide. Do not equate recognition questions with writing/speaking assessment.

Every `data` lesson requires a shared `chart` alongside `questions`:

```json
{
  "type": "bar",
  "title": "Sample seedlings grown",
  "labels": ["Beans", "Peas", "Corn"],
  "counts": [3, 5, 4],
  "unit": "seedlings",
  "scale": 2
}
```

`bar` counts are numbers of displayed blocks, so this example represents 6, 10, and 8 seedlings. `line` counts are numbers of X marks at each measurement label; line plots require `scale: 1`. Use 2–6 distinct labels, matching integer counts from 0 to 10, and an integer scale from 1 to 10. Numeric line-plot labels must be nonnegative whole numbers, decimals, or fractions with nonzero denominators, in increasing, equally spaced order; validation rejects a misleading axis. Keep prompts, answers, guidance, and graph data consistent. Charts belong only in `data`; passages belong only in `reading` and `informational`.

Run `npm test` and `npm run build` after edits. Both validate all seven packs, including lesson completeness, question counts, choices, passages, guides, and charts. Reviewed answer fixtures are in `src/grades.test.ts` and `src/curriculum.test.ts`; the latter also calculates graph totals, fraction examples, and measurement results. When intentionally replacing those examples, review the math and update the relevant fixture. Reload and start a new round to preview edits. Rebuild and deploy `dist` to publish them. Existing grade scores are not automatically reset when you replace questions.

`WebPage` JSON-LD. They require no JavaScript, cookies, sign-in, external fonts, or
learning-progress reads. They contain no learner-specific data.

Before a production build, set **`PUBLIC_SITE_URL=https://your-actual-domain`** to
the real HTTPS origin (no subpath, query, credentials, or fragment). This adds canonical
URLs, Open Graph URLs, a generated `sitemap.xml`, and its location in `robots.txt`.
Without it, canonical URLs and the sitemap are intentionally omitted rather than
guessing an unpurchased domain. This is a public build setting, not a secret.
The deployment assumes hosting at the domain root, as does the existing app.

Deploy the entire `dist` directory. Configure the host to serve existing files and
directory `index.html` files **before** any SPA fallback. `/learn/grade-3/` must return
that guide's HTML, not the app shell; unknown `/learn/...` routes should return 404.
Use one preferred HTTPS hostname and redirect alternatives. Preview deployments should
have host-level indexing disabled (for example `X-Robots-Tag: noindex` or access control);
do not submit preview URLs. The interactive app shell has `noindex,follow` so search
entry points are the public guides, not an adult sign-in screen. This is not a security
boundary: authorization remains necessary for private data.

`llms.txt` is an optional plain-text guide linking the same public pages and stating
their limits. It is not a universal AI discovery standard, an access-control mechanism,
or a promise of search/AI visibility. No crawler cloaking, keyword stuffing, fabricated
ratings, or automatic search submission is included. After deployment, verify real
URLs, submit the sitemap through the search engines' webmaster tools, and maintain
accurate content as features and operator practices change.

Editorial source is in `src/site-content.ts`; rendering and discovery assets are in
`src/site-pages.ts`. The privacy guide describes software behavior and **does not**
replace the operator's legally appropriate notice or consent/school authorization.

## My learning path

Open **My learning path** in the main navigation. It follows the learner's saved grade
(Pre-K through Grade 5); changing grade still happens on the dashboard.
An optional **eight-question practice check** samples four English and four Math skills.
There is no timer, points, streak, badge, competition credit, or automatic grade change.
Adults can read and help operate it. Immediate explanations encourage learning; only the
first submitted answer to each question counts in that check.

Completing all eight saves the latest correct/try-together result and local calendar date
per sampled skill in optional `Progress.pathChecks`, plus the number of completed checks
per grade. Typed answers and unfinished checks are not saved. Three rotating skill groups
cover all 16 activities; subsequent cycles rotate through the five existing questions in
each activity. The small question bank eventually repeats and is shared with adventures.
Existing saves without this optional field still load. Results use existing guest storage
or configured account sync, privacy export, and learning erasure. No new backend migration
or third-party service is required.

Recommendations prioritize missed check questions, unexplored skills, continued practice,
then review. The first three are offered as next steps; every skill remains available.
Practice opens the normal grade-specific adventure with its usual scoring.
The expandable grown-up view displays per-skill check dates/results and existing best
adventure scores. A missed check stays visible until that skill is sampled again; a best
round is not a recent trend, and check dates may differ across skills.

This is **rule-based practice guidance, not a validated diagnostic, adaptive difficulty,
standards mastery assessment, or full IXL-equivalent platform**. Results are client-reported,
can reflect adult help or remembered questions, and must not be used for grading or
placement. Class rosters, assignments, longitudinal teacher reports, larger reviewed
question banks, and validated assessment remain separate future work.

## Optional voice help: Pre-K through Grade 2

**Privacy default:** both synthesis and recognition are disabled unless the operator completes the privacy configuration below and separately sets `VITE_BROWSER_SPEECH_ENABLED=true`. Feature availability and an in-page adult checkbox alone do not enable voice. This intentionally changes the earlier optional-voice default because browsers may process speech off-device.

Select **Pre-K, Kindergarten, Grade 1, or Grade 2** to show **Listen & speak**. Voice is optional and off by default. This is U.S. English support, not pronunciation assessment or a replacement for adult help.

- **Read this aloud** reads the current question and labeled choices; **Read story aloud** reads the shared passage. The optional **Read each new question and feedback aloud** checkbox enables automatic read-aloud for subsequent screen changes. Stop voice cancels current playback/listening; uncheck automatic reading to keep later questions quiet.
- To enable the microphone, a grown-up opens **Grown-up microphone permission & privacy**, reviews the notice, and checks the permission box. This is only an in-page opt-in; the browser separately asks for actual microphone permission. It does not prove age or meet all school/child-privacy obligations.
- Press **Listen for one command** for each utterance. Recognition is one-shot, has a 15-second limit, and never starts automatically or resumes after a result, failure, navigation, or tab hiding. Press **Stop voice** to cancel. A new Listen press stops read-aloud first so the app does not intentionally listen to its own voice.
- Say **Home**, **Adventures**, **English**, **Math**, **Read question**, **Read story**, **Hint**, **Next**, **Play again**, or **spelling bee** when the action is available. In Adventures, say **start activity one** through **start activity nine**, matching the visible card numbers. Next only advances after feedback; leaving unfinished work uses the normal confirmation dialog.
- For multiple-choice questions, say **option A**, **option B**, etc., or an exactly recognizable unique answer. Use the option letter when choices differ only in capitalization or sound alike. The app does not guess among ambiguous choices or grade recognition failures as wrong.
- For spelling, say **separate letter names**, such as **C, A, T**. A whole spoken word such as “cat” is not accepted as a spelling attempt. Browser recognition can still mishear letter names; use the keyboard whenever needed.
- A spoken answer is **proposed, not scored immediately**. Review the displayed answer (also read back when synthesis is available), then press **Use this answer**, or press Listen again and say **Confirm answer**. Cancel answer clears it. Transcripts and pending choices are discarded on question/screen changes; delayed callbacks cannot answer a later question.

Read-aloud uses the browser's speech synthesis voices. Speech recognition uses `SpeechRecognition` or `webkitSpeechRecognition` if available, over **HTTPS or localhost**. Browser/device support, English voices, service availability, microphone permission, and network requirements vary; feature detection is not a guarantee of working audio hardware or a connected provider. Unsupported features show a visible explanation and leave all buttons/typing usable. Ordinary Grade 3–5 screens do not show voice controls, but the spelling bee offers voice at every level.

**Privacy:** the app does not create audio recordings, upload audio to Supabase, or persist recognized transcripts. Transcripts are held briefly in page memory to display/confirm an answer. Browser speech recognition may send audio to the browser/provider; a synthesis voice may also use an online service. Provider processing and retention are outside this app's control. There is no promise of offline/local-only speech. Do not speak personal information. Review provider and school policies before enabling microphone use for children. The microphone checkbox and auto-read preference are not saved to localStorage or accounts; changing to an unsupported level, opening a game dialog, switching accounts, or reloading may reset them. Browser-level permission can be revoked in site settings.

Voice stops on question/feedback/navigation changes, when the page is hidden, when dialogs open, and on unmount/sign-out. It does not automatically operate account controls, rewards, avatar choices, or permission dialogs. Read-aloud and microphone use mark a normal quiz question as assisted, so it cannot earn a speed bonus; correct-answer/perfect/daily rewards still apply. Spoken spelling is practice, not a standardized or proctored assessment.

Automated coverage uses mocked speech APIs to exercise permissions, failures, cancellation, confirmation, navigation, and scoring. Before deploying to families, check real audio output and microphone recognition on the intended browsers/devices with a consenting adult, including denied permission, offline behavior, and mobile backgrounding. No real child audio or microphone recording is used by these automated checks.

## Solo Spelling Bee Championship

On the dashboard or Adventures page, choose a level and press **Start spelling bee**. This is **solo practice, not a live multiplayer, official, or supervised championship**. It uses the chosen level's existing five spelling entries, not five additional questions. Pre-K copies/explores five individual letters; Kindergarten–Grade 5 practice complete words.

Press **Hear the bee word** (repeat as often as needed), then type the word or use confirmed spoken letter-by-letter input. **Read the clue** gives the existing spelling prompt. If synthesis is unavailable, a grown-up can open the clearly labeled word card and read aloud. The word is intentionally available for adult help, and clues/hints may reveal letters: this is not a secure test. No external dictionary or competition word list is copied or downloaded.

Every learner completes five entries, including after mistakes. There is no elimination or time limit. Feedback explains each answer. The final screen gives a 0–5 score, encouragement, and replay; 5/5 earns the on-screen “practice bee champion” celebration, not a new persistent badge or official award. Rewards are +10 per correct, +50 for five correct, and the same once-per-day completion bonus used elsewhere. **Bee rounds never award speed bonuses.**

Best bee scores are stored separately per level in optional `Progress.beeBestRounds`; ordinary spelling best scores and mastery are not overwritten or awarded from a bee. Points, correct/answered totals, rounds, streaks, daily missions, and chest eligibility still accumulate. Existing saves without bee scores remain valid; private account syncing uses the existing progress record when Supabase is configured. No transcript or audio is included in that record.

## Coding Cove: Grades 3–5

Open **Coding Cove · 3–5** in the main navigation, or **Explore Coding Cove** on the dashboard/Adventures page. The selected learning grade is used for Grades 3–5; otherwise coding starts at Grade 3. A separate coding-grade selector lets learners explore any of these levels without changing their English/Math grade.

There are **18 original robot-delivery puzzles**, separate from the 560 English/Math questions. Every grade offers six lessons in order, but none are locked:

| Grade | Learning progression |
| --- | --- |
| 3 | Move in sequence; robot-relative turns; debug a broken plan; repeat moves; check a clear path; define and call Helper |
| 4 | Longer sequences/routes; trace and repair; loops for two route segments; repeated if/else decisions; reuse a route function |
| 5 | Longer routes and debugging; nested loops; repeated decisions; combine loops, conditions, and function calls |

Each lesson includes a short explanation, mission, hint, visual map, and equivalent row/column table. Use the keyboard-accessible block selector and **Add block**, **Up**, and **Remove** controls to build a plan. Repeat groups hold nested instructions; conditions have Then/Else branches; Helper is a named function called from the main plan. Calls are unavailable inside Helper, so recursion is not part of this starter language.

**Run my program** or **Run this plan** executes from the original robot position every time and shows the outcome. **Rewind**, **Previous step**, and **Next step** walk through a deterministic execution trace, including turns, branches, and helper calls. Editing clears the old run; **Reset robot** preserves the block plan. All execution is synchronous and bounded, with no animation or speed requirement. Wall collisions, incomplete/empty programs, unmet lesson requirements, invalid repeats, and limits produce visible feedback rather than a wrong-answer penalty. Repeats allow 2–8 iterations, nesting is limited to three group levels, programs to 40 total blocks, and execution to 200 instructions. Some missions also impose smaller block budgets to practice reuse.

The first successful solution of each distinct grade/puzzle earns **+10 points**; replay earns no extra points. Completion IDs are stored in optional `Progress.codingCompleted` and use the existing guest persistence or configured account sync. Older saves remain valid. Coding does not change five-question round totals, English/Math mastery, daily mission completion, streaks, or chest eligibility. Block plans and execution traces are temporary and are not saved or sent to account storage. Changing lessons or leaving a nonempty plan asks for confirmation; browser reload/close warnings depend on browser support.

This is a small, original teaching language, **not JavaScript, an arbitrary-code editor, standards certification, or a full computer science course**. “Advanced” here means combining foundational concepts, not professional software development. Programs cannot access files, the network, account data, or execute arbitrary scripts: the interpreter handles only the predefined block types, with no `eval` or generated JavaScript. Puzzle definitions, learning text, maps, and reviewed solution fixtures are in `src/coding.ts`; they are not part of the English/Math `.txt` schema. ### Reliability, privacy, and recovery

The server stores USD amounts in integer cents and currently permits whole-dollar requests between
$1 and $500 (the UI offers four preset amounts). Donation-intent creation is limited to five per
adult account/hour, including failed attempts. A fixed request UUID and separate capture UUID are
used as PayPal idempotency keys. A create retry reuses the same intent/amount; an approved/completed
order is read from PayPal before capture so a repeated capture request does not blindly charge again.
An unresolved create attempt expires after five hours if no provider order was stored, rather than
reusing an expired PayPal idempotency window. The frontend keeps the current attempt ID in page
memory; do not reload/start over after an uncertain failure without checking PayPal first.

The return query contains an opaque donation UUID, PayPal's token and possibly its payer ID, not
learner content. The server ignores the supplied PayPal token/payer ID and finds the order by its
stored owner/UUID. No capture happens automatically on return; confirm as the adult. Successful
capture handling removes those query fields. If sign-in expires, request a fresh adult sign-in and
use the preserved donation return reference; sign-in redirect allowlists must permit the app URL
with these query parameters (use your host's supported matching rules). A cancelled return is not
payment evidence; review Activity before starting again.

Only verified, matching USD events enter the admin ledger. Event IDs are unique, so redelivery is
idempotent. Out-of-order events append rather than overwrite statuses; refunds can reconcile through
a fixed PayPal capture-details lookup even when the completed event has not arrived yet. Unknown
orders, invalid signatures/amounts, and service failures return non-success responses so PayPal can
retry. Unknown orders can also indicate another checkout integration on the same REST app: use a
dedicated app and investigate rather than crediting unrecognized payments. There is no scheduled
reconciliation/import job; monitor failed Edge requests/PayPal delivery logs and redeliver verified
notifications or reconcile manually. Do not log full webhook bodies, authorization headers, secrets,
donor information, or provider responses. Public endpoints also need operational abuse/rate monitoring;
the per-account intent cap is not a network-wide anti-abuse service.

Financial records are separate from learner progress. They contain an adult auth reference (not a
child profile), opaque request/order/capture/refund/event IDs, amounts/currency, environment, and
timestamps. Provider payer names, email, addresses, card details, and raw webhook bodies are not
persisted. Supabase/Auth, hosting, and PayPal still have their own records; the adult-auth reference
can identify an adult. Learning-data erasure deliberately does not delete financial records. Deleting
an adult auth identity nulls the financial account reference while preserving the financial ledger.
The operator must define lawful financial retention, backup expiry, access/deletion processes and
any required accounting evidence; there is no automatic financial retention cleanup job. Review the
financial-data policy alongside the child-privacy notice before enabling donations.

No donation unlocks learning content, scores, badges, rewards, or standings. The adult checkbox is
an attestation, not identity/age verification. No charitable status or tax deductibility is claimed.
The operator must verify recipient eligibility and provide accurate legal/recipient/refund information.

Validation commands: `npm test` covers mocked PayPal/server authority and frontend flows;
`npm run test:payments-db` runs the real migration in isolated PostgreSQL/PGlite to check admin
assignment/revocation, denied direct writes, identity isolation, rate limits, idempotency and paging.
`npm run build` type-checks both the frontend and Edge Function code. These checks do not prove a
deployed payment integration works; sandbox acceptance is still a launch requirement.

Official PayPal API schemas used for payload verification:
[Orders v2](https://github.com/paypal/paypal-rest-api-specifications/blob/main/openapi/checkout_orders_v2.json),
[Payments v2](https://github.com/paypal/paypal-rest-api-specifications/blob/main/openapi/payments_payment_v2.json),
and [Webhook signature verification](https://github.com/paypal/paypal-rest-api-specifications/blob/main/openapi/notifications_webhooks_v1.json).
The interactive developer reference returned only a cookie banner in this environment, so request/
response shapes were checked against these official PayPal specifications instead.

### Cloud save behavior

Account progress loads from Supabase before the learning dashboard opens. Progress-changing actions queue serialized cloud saves; the header reports saving/saved state. Cloud play does not write progress into the guest `localStorage` key. Sign-out is disabled while saves are pending.

Failed saves display a blocking recovery dialog and preserve unsynced progress **in this open page's memory**; keep it open and retry. The app warns before leaving with pending changes, but a browser crash or forced close can still lose unsynced work. It does not claim offline cloud sync. When another device/tab updates the same record, an optimistic revision check prevents overwriting the newer save. The adult can explicitly discard local unsynced changes and reload the latest cloud version; there is no automatic conflict merge. Opening/signing in on a device loads the latest saved account record; idle tabs are not realtime subscriptions.

In the deployed database, confirm anonymous requests cannot access progress, and account A cannot select, insert, or update account B's record. ### Questions, answers, and stories

Each of the seven question-bank files contains an array of **exactly five** question objects to preserve five-question rounds and scoring. Edit existing questions or replace them with your own original/licensed material. Each question needs nonempty `prompt`, `answer`, `hint`, and `explanation`. Multiple-choice activities also need 2–6 distinct `options`; `answer` must exactly match one option. The app shuffles choices for play, so never depend on their displayed order.

Here is the structure of one reading question (keep four other question objects in the file):

```json
{
  "prompt": "What did Mia plant?",
  "answer": "a seed",
  "options": ["a seed", "a toy", "a rock", "a book"],
  "hint": "Look at the first sentence.",
  "explanation": "The story says Mia planted a seed.",
  "passage": "Mia planted a seed in a pot. She watered it every day.\nSoon, a green leaf peeked out!"
}
```

Only reading questions have `passage`. Use `\n` inside the JSON string for visible story line breaks. Only geometry questions have `shape`, which must be `triangle`, `square`, `circle`, `rectangle`, or `pentagon`; those names select existing illustrations. Spelling questions omit `options` because learners type their answer. HTML and website links in these fields are displayed as plain text, never executed or fetched.

### Generated Math and teammate practice

In `math-templates.txt`, keep all five template names and their `prompt`, `hint`, and `explanation` fields. Change wording around the supported placeholders:

| Template | Supported placeholders |
| --- | --- |
| `addition`, `subtraction` | `{a}`, `{b}`, `{answer}` |
| `multiplication`, `division` | `{a}`, `{b}`, `{product}`, `{answer}` |
| `patterns` | `{start}`, `{n1}`, `{n2}`, `{n3}`, `{step}`, `{answer}` |

For example, change the addition prompt to `"What is {a} plus {b}?"`. ## Honest first-version boundaries

This is a **single-learner-per-adult-account app** with optional private, asynchronous practice rooms when Supabase and the room migration are configured. The original Leaderboard/Team corner classmates, friends, weekly scores, and 120-answer team baseline remain explicitly fictional demos. The learner's row on that demo leaderboard is all-time, not a real weekly ranking. Private room standings are a separate server-backed weekly view. There is no winner-based competitive payout: the +100 personal reward is a completion-based daily mission to encourage effort rather than beating other children.

There are no public profiles, chat, full classroom administration, real-time races, ads, or purchases. Authentication, private progress sync, and invite rooms are implemented but need your Supabase configuration and migrations. Personal points/dates and completed-round reports are client-calculated, not tamper-proof. Room credit caps and week/day windows are server-controlled, but that does not verify academic work. Neither kind of score is appropriate for competitive prizes. The adult checkbox is an attestation, not age verification or a complete child-privacy compliance program. Before a public school/child deployment, establish consent, retention, deletion, regional hosting, and applicable legal policies. Supabase necessarily handles adult email addresses, authentication metadata, progress, and optional room membership/credit records. No adult email is displayed on learning screens.

Each grade-selected activity contains five fixed questions, repeated with shuffled choices on replay. Each grade has one story and one nonfiction text, each shared across five comprehension questions. Content is not adaptive or a complete curriculum. Sentence/writing quizzes use choices; extended writing is an unscored paper task, not a free-writing editor. Treasure rewards are cosmetic. The privacy center exports only the current learning save, not a complete provider/account/room record. Clearing site data removes guest progress and local sign-in state, not the adult account's saved cloud record. A malformed guest save displays an explicit warning; the next progress-changing action starts a new valid save. Malformed cloud records block loading instead of silently resetting account progress.

Fonts use the installed/system fallbacks; there are no external Google Fonts requests. There is no analytics or third-party game content.
